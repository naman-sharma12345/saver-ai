4.4 Smart Budget Recommender (K-Means Clustering)

Module: ml/smart_budget.py

Algorithm: K-Means Clustering

Features: Per-category spending averages (8D)

Preprocessing: StandardScaler normalisation

k Selection: min(max(2, n_users/2), 5)

n_init: 10 random restarts

Algorithm Flow

1. Extract category spending profiles for ALL students
2. Build feature matrix [n_students × 8_categories]
3. StandardScaler normalisation (zero mean, unit variance)
4. K-Means clustering with optimal k
5. Identify user's cluster assignment
6. Compute cluster-mean spending per category
7. Apply headroom factor based on spending persona
8. Cap individual categories at 40% of allowance
9. Scale total to ≤95% of allowance

Spending Personas

PersonaSpending RatioHeadroom Factor
Frugal Saver≤ 50%1.10× (10% above cluster avg)
Balanced Spender≤ 75%1.05×
Active Spender≤ 95%0.95× (encourage reduction)
Over-Spender> 95%0.85× (aggressive reduction)

Fallback (Heuristic — 50/30/20 Rule)

When fewer than 2 users exist (insufficient for clustering), the system uses the 50/30/20 rule adapted for students:

  • 50% Needs: Food (25%), Transport (10%), Bills (8%), Health (7%)
  • 30% Wants: Entertainment (15%), Shopping (15%)
  • 20% Growth: Study Materials (12%), Other (8%)

4.5 Recurring Expense Detector

Module: ml/recurring_detector.py

Technique: Frequency Analysis + Coefficient of Variation

Min Occurrences: 3 (to detect pattern)

Regularity Threshold: CV-based score ≥ 0.3

Algorithm

1. Group expenses by normalised (description + store_name)
2. For each group with ≥3 occurrences:
   a. Sort by date, compute time deltas between consecutive expenses
   b. Calculate mean_delta, std_delta
   c. Coefficient of Variation: CV = std / mean
   d. Time regularity = max(0, 1 - CV_time)
   e. Amount regularity = max(0, 1 - CV_amount)
   f. Composite score = 0.7 × time_regularity + 0.3 × amount_regularity
3. Filter: keep only patterns with score ≥ 0.3
4. Predict next occurrence: last_date + mean_delta

4.6 Savings Goal Predictor (Monte Carlo Simulation)

Module: ml/savings_goal.py

Technique: Monte Carlo Simulation

Simulations: 1,000 iterations

Distribution: Normal (fitted to historical)

Algorithm

1. Fit Normal distribution to historical monthly spending:
   μ = mean(monthly_totals), σ = std(monthly_totals)
2. For each of 1000 simulations:
   a. For each future month:
      - Sample spending ~ N(μ, σ), clamped to ≥0
      - monthly_savings = allowance - spending
      - cumulate
   b. Record total_savings for this simulation
3. Probability = count(total_savings ≥ target) / 1000 × 100
4. Compute percentiles: P10, P25, P50, P75, P90

Probability Interpretation

ProbabilityAssessment
≥ 90%Excellent — current habits strongly support goal
≥ 70%Good — minor adjustments needed
≥ 40%Moderate — significant reduction in spending required
< 40%Challenging — consider extending timeline or reducing target

5. Key Features Detail

5.1 OpenStreetMap Store Discovery

The system queries the Overpass API to fetch real-world store locations:

  • Searches within configurable radius (1–25 km)
  • Maps 60+ OSM amenity/shop types to 8 app categories
  • Estimates price levels from OSM tags (cuisine, brand, fees)
  • Caches discovered stores in the database to minimise API calls
  • Graceful fallback to local DB when API is unavailable

5.2 Geospatial Cheaper Alternatives

Uses the Haversine formula via GeoPy to:

  1. Find the store associated with an expense
  2. Query stores with lower price levels within the radius
  3. Calculate estimated savings based on price level differential
  4. Rank by distance for practical recommendations

5.3 AI Insights Page (New Feature)

A dedicated insights page that provides deep ML-powered analysis:

  • Spending Persona: K-Means cluster assignment with visual persona card
  • Smart Budget Recommendations: AI-optimised per-category budgets
  • Recurring Expense Detection: Auto-detected subscription patterns with next occurrence prediction
  • Savings Goal Simulator: Monte Carlo-powered probability calculator

5.4 Parental Monitoring

Parents can link to student accounts and view:

  • Per-student spending summaries and category breakdown
  • Financial health scores and budget adherence rates
  • Anomaly alerts for unusual spending patterns
